# 个人 Coding Agent 第一阶段设计

记录日期：2026-10-31。本文保存当前设计共识与工程建议，不代表对应功能已经实现。

## 1. 目标与范围

开发一个在本机运行、供个人使用的 Coding Agent，根据自然语言需求修改项目中的函数，覆盖代码检索、理解、修改、测试及运行结果验证。

首版建议从 Python 项目的单个目标函数开始，允许同时补充相关测试，通过 CLI 执行单个任务。目标函数可能依赖同文件定义、导入和调用方，理解代码时需要按需读取这些上下文。

## 2. 已确认的设计共识

| 项目 | 约定 |
| --- | --- |
| 开发语言 | Python |
| 数据与参数校验 | Pydantic |
| 状态存储 | SQLite |
| 模型接入 | DeepSeek API，配置从已有 `.env` 加载 |
| 修改预算 | 实现与修复合计最多三次，首次实现计一次，最多再修复两次 |
| 检索范围 | 暂时不做向量检索、多语言解析和 LSP |
| 验收顺序 | 理解用户需求 → 确定预期效果 → 编写验收测试 → 编写实现 → 运行验收测试和原有测试 |
| 成功判定 | 由程序依据实际检查与测试结果判定，模型负责解释结果 |
| 变更交付 | 编写或更新相关测试，所有测试和验证通过后，为完成的改动创建 Git commit |

仓库内的变更要求见 [AGENTS.md](../../AGENTS.md)。

## 3. 工程实施建议

以下内容是首版实现的推荐方案，具体依赖版本和配置在编码时锁定。

| 环节 | 推荐方案 | 作用 |
| --- | --- | --- |
| 环境与依赖 | Python + uv | 管理解释器、虚拟环境和依赖锁文件 |
| 数据模型 | Pydantic v2 | 校验任务、工具参数、工具结果和最终报告 |
| 模型调用 | DeepSeek API + 经过实际兼容验证的 SDK | 发起请求、处理工具调用与结果回传 |
| 执行流程 | 普通 Python 显式控制流程 | 控制阶段、修改次数、终止条件和结果判定 |
| 代码检索 | ripgrep + 按行读取文件 | 查找函数定义、调用位置和相关测试 |
| Python 结构分析 | 标准库 ast | 辅助定位函数、类、导入和源代码范围 |
| 局部修改 | 自己实现受控文本替换 | 校验文件版本、匹配原文并生成 diff |
| 命令执行 | 标准库 subprocess | 运行检查、测试和验收程序，记录输出及退出码 |
| 检查与测试 | pytest + Ruff | 验证行为、检查代码规范并生成测试报告 |
| 持久化 | 标准库 sqlite3 + 本地产物目录 | 保存状态、事件和报告位置 |
| 版本管理 | Git CLI，可配合 worktree | 记录基线、管理任务改动和提交结果 |

先以简单模型调用循环完成闭环。PydanticAI 可在后续需要减少工具参数、结构化输出和纠错处理的重复代码时评估。

本机运行指编排、文件操作、执行器和数据库位于本机；模型通过 DeepSeek API 调用。

## 4. 任务执行流程

1. 接收需求与目标仓库，记录任务标识、Git 基线和工作区状态，保留用户已有改动。
2. 运行原有测试，记录测试基线；既有失败必须明确记录，不能忽略后宣称全部通过。
3. 检索函数、调用位置和相关测试，读取必要的导入、类型与项目配置。
4. 明确预期效果，包括输入、输出、边界情况，以及适用时的异常、标准输出或文件副作用。影响行为的歧义先向用户澄清。
5. 根据需求编写验收测试，将预期效果转为可执行断言，并固定验收版本。
6. 在原始实现上运行验收测试，确认未满足需求的行为能被检测到。如果原始实现已经满足需求，执行所需检查后报告无需修改。
7. 在修改预算内调用模型编写或修复实现，校验并应用局部变更。
8. 执行代码检查、验收测试和相关测试，再运行完整的原有测试。失败信息反馈给模型，进入下一次修改尝试。
9. 全部测试和验证通过后，保存最终 diff 与报告，创建对应 Git commit，并记录提交标识。
10. 修改预算耗尽仍未通过时，结束任务并保存失败证据，明确报告失败或未完成。

没有实际执行、未收集到预期测试、验收用例被跳过或测试报告无法读取时，均不能作为成功依据。

## 5. 三次修改预算

“修改尝试”指请求模型生成或修复一轮实现变更。首次实现计第 1 次，随后最多两次修复。

| 尝试 | 内容 | 后续处理 |
| --- | --- | --- |
| 第 1 次 | 首次实现 | 检查与测试通过则结束，否则进入第 2 次 |
| 第 2 次 | 根据失败证据修复 | 通过则结束，否则进入第 3 次 |
| 第 3 次 | 最后一次修复 | 执行最终检查，通过则成功，否则结束并报告失败 |

需求分析、代码检索和编写验收测试不占用这三次修改预算。这是实现与修复的预算，不等同于整个任务的 API 请求总数；包含实现生成的请求不能以分析请求的名义绕过计数。

尝试次数需要持久化，同一任务的继续执行不能重置预算。API 传输重试、任务总请求数、总耗时和输出大小也应有独立上限，具体数值及传输失败的计数细节在实现时补充。

## 6. 验收测试约束

- 预期效果来自用户需求及澄清结果，并记录必要假设，避免根据当前实现反推期望值。
- 验收测试在实现修改之前生成并固定保存，记录其版本或内容哈希。
- 修复阶段围绕实现修改，不能通过放宽断言、删除测试或增加跳过标记取得通过。
- 发现验收测试本身有问题时，单独说明依据；需求存在歧义时先澄清，再形成有记录的新验收版本。
- 原有测试与新需求冲突时，应说明冲突，不能静默修改测试期望值。
- 正常输入、需求相关边界和既有行为需要覆盖；运行结果按场景断言返回值、异常、输出或副作用。
- 新增验收测试与原有回归测试都必须执行，并保留命令、退出码和结构化测试报告。

例如，需求为“空列表返回 `None`，非空列表保持原有平均值计算行为”，则验收至少覆盖空列表、单元素列表和普通非空列表。原始实现应在需求未满足的用例上暴露差异，已有正确行为仍需回归验证。

## 7. 模块与工具接口建议

模块应通过小接口集中处理相关行为，避免把模型协议、文件校验和测试判定散落到流程代码中。

| 模块 | 职责 |
| --- | --- |
| 任务执行模块 | 管理执行阶段、修改预算、终止条件和最终结果 |
| 模型调用模块 | 封装 DeepSeek 请求、工具消息、输出解析和调用量记录 |
| 工作区模块 | 完成检索、读取、路径校验、局部修改和 diff 获取 |
| 验证模块 | 运行预设检查与测试，解析报告，输出可判定的验证结果 |
| 状态存储模块 | 保存任务、事件、尝试次数和产物引用 |

首版可向模型提供五个工具：

| 工具 | 输入与行为 | 输出 |
| --- | --- | --- |
| `search_code` | 按关键词或模式搜索项目代码 | 文件位置、行号、匹配片段与截断信息 |
| `read_file` | 按文件及行范围读取上下文 | 内容、文件版本信息与截断信息 |
| `edit_file` | 提交路径、原文、新文与预期文件哈希 | 修改结果及 diff，或明确的校验错误 |
| `run_checks` | 执行已配置的检查、测试和验收命令 | 退出码、报告位置和失败摘要 |
| `get_diff` | 获取相对任务基线的变更 | 文件列表与 diff |

最终状态由执行程序计算。模型输出“完成”不能代替验证模块的实际检查。

## 8. 文件修改与命令执行

文件修改至少满足：

- 路径解析后位于授权工作区内，并处理符号链接或目录联接造成的越界。
- 修改前文件哈希与读取时一致，原文必须恰好匹配一次；不满足时拒绝写入并要求重新读取。
- 保留原文件编码和换行方式，通过临时文件与原子替换完成写入。
- 验收测试的固定版本在实现修复阶段受到保护。
- 记录修改前后版本与 diff，保留用户原有未提交改动。

命令执行至少记录工作目录、参数列表、耗时、退出码、标准输出和标准错误。使用参数列表调用进程，配置命令范围、超时和输出长度上限；Windows 上需要处理超时后的子进程清理。

虚拟环境用于管理依赖，Git worktree 用于管理任务改动。执行权限限制需要由执行器另行落实。

## 9. 状态、产物与任务结果

SQLite 初期可保存三类记录：

- 任务：需求、预期效果、必要假设、仓库、Git 基线、阶段、修改次数、最终状态和最终 commit。
- 事件：模型消息、工具调用、参数校验错误、执行结果、时间及调用量信息。
- 产物索引：固定验收版本、补丁、完整日志和测试报告的本地位置及内容哈希。

大日志和报告保存在本地目录，数据库保存引用。配置从 `.env` 加载，凭据不进入提示词、日志、报告或 Git commit。

成功报告包含修改摘要、执行过的检查与测试、实际结果、diff 和 commit。失败报告包含停止原因、已用修改次数、未通过的检查、执行日志及当前 diff。无需修改时记录验证证据，并说明未产生代码变更。

## 10. 测试与验收场景

Agent 自身的确定性测试建议使用临时仓库与可控的模型响应，真实 DeepSeek 调用用于少量端到端评估。实现前的场景清单如下，当前仅为待实现的测试规格。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 首次实现满足需求 | 实现尝试次数为 1，验收与原有测试通过，创建 commit |
| A02 | 首次实现失败，第二次修复成功 | 失败证据反馈给模型，次数为 2，保留两次记录 |
| A03 | 第三次修复成功 | 最终次数为 3，检查通过后报告成功 |
| A04 | 三次修改均失败 | 不发起第 4 次实现请求，保存 diff 和失败证据 |
| A05 | 原始实现已满足需求 | 验收与原有测试执行后报告无需修改，实现次数为 0 |
| A06 | 需求包含影响行为的歧义 | 先请求澄清，未明确前不修改实现 |
| A07 | 工具参数无效、文件版本过期或原文不唯一 | 返回明确错误，文件保持原样 |
| A08 | 文件路径经解析后越出工作区 | 拒绝读取或修改越界目标 |
| A09 | 命令超时或输出超过上限 | 结束或限制执行，清理相应进程并保留错误信息 |
| A10 | 修复时尝试削弱或跳过固定验收测试 | 拒绝该变更，不能以此报告成功 |
| A11 | 验收通过但原有测试失败，或预期测试未执行 | 报告未通过，剩余预算内继续修复 |
| A12 | 同一任务中断后继续 | 读取已记录次数，不重新获得三次预算 |
| A13 | 参数校验成功但实际文件或测试操作失败 | 返回真实失败，不把参数合法当作执行成功 |
| A14 | 任务报告与日志生成 | 可追踪需求、固定验收版本、每次尝试、验证结果及 commit，且不包含凭据 |

本文档的格式、编码和本地链接由 [文档校验测试](../../tests/test_product_docs.py) 检查。文档校验通过不代表上述 Agent 行为已经实现或通过测试。

## 11. 实现阶段需细化的事项

- DeepSeek 模型名称、SDK、配置字段和工具调用兼容性。
- API 重试策略，以及总请求数、总时间和输出大小上限。
- 目标项目的解释器、依赖准备、检查命令和测试命令配置。
- 验收测试的保护方式、版本修订流程及已有测试冲突处理。
- SQLite 表结构、任务中断后的恢复规则和 Git worktree 使用方式。
- 首批真实模型评估样例及成功率、尝试次数、耗时和调用量的记录方式。
