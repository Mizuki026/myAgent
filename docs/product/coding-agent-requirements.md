# 个人 Coding Agent 总需求文档

版本：v1.0。日期：2026-11-01。

## 1. 产品目标

开发一个在 Windows 本机运行、供个人使用的 Coding Agent。用户通过本机 Web 提交自然语言需求，由 Agent 理解项目、规划任务、检索和修改代码、执行开发命令、验证结果，并交付可追踪的修改成果。

产品覆盖现有项目维护和小型项目新建，优先支持 Python、JavaScript 和 TypeScript 项目。

产品直接提供本机 Web，不将 CLI 作为使用入口。用户应能够在网页中完成需求沟通、任务控制、过程查看和结果检查。

## 2. 功能需求

### 2.1 用户交互与项目操作

| 编号 | 名称 | 需求 |
| --- | --- | --- |
| FR-001 | 本机 Web 入口 | 用户能够通过本机网页提交需求、查看任务计划和进度、执行日志、代码差异、验证结果及最终报告。 |
| FR-002 | 自然语言交互 | 支持围绕任务进行自然语言对话、回答澄清问题和补充需求。影响代码行为的歧义应先向用户澄清；需求发生变化时，应同步调整任务目标并保留变化记录。 |
| FR-003 | 项目选择 | 用户能够选择已有项目或指定新项目位置。无法访问或无法开展工作的项目应给出明确原因，不得误报已开始或已完成。 |
| FR-004 | 代码检索与理解 | 能够检索相关文件、函数、调用位置和测试，读取相关代码，结合上下文理解需求，并向用户提供代码位置依据。 |
| FR-005 | 现有项目维护 | 支持根据需求编写和修改代码，完成跨文件功能开发、缺陷修复和重构；识别对相关代码与既有行为的影响。 |
| FR-006 | 小型项目新建 | 支持根据明确需求创建小型项目，生成所需源码、项目配置和测试，完成必要的初始化与运行验证，并向用户说明使用方式。 |
| FR-007 | 代码语言范围 | 优先支持 Python、JavaScript 和 TypeScript 项目的代码检索、理解、生成、修改及验证。 |

### 2.2 任务规划与执行

| 编号 | 名称 | 需求 |
| --- | --- | --- |
| FR-008 | 自动规划 | 根据用户目标拆解子任务，明确任务依赖、工作范围、完成条件和状态；根据执行情况调整计划，并向用户展示变化。 |
| FR-009 | 自主执行 | 在用户发起并授权的任务范围内自动执行，无需逐步确认。遇到影响行为的歧义或需要超出授权范围时，再询问用户。 |
| FR-010 | 开发命令执行 | 支持依赖安装、项目初始化、测试、检查、构建等本机开发命令，并展示执行进度、结果和失败原因。 |
| FR-011 | 本地开发服务 | 支持启动、查看和停止任务所需的本地开发服务，向用户展示服务状态、可用的访问地址和日志，不影响用户原有服务。 |

### 2.3 多 Agent 协作

| 编号 | 名称 | 需求 |
| --- | --- | --- |
| FR-012 | 预置角色 | 使用系统预置的主控、探索、编码、审查等 Agent 角色，向用户展示不同角色的职责和工作情况。 |
| FR-013 | 自动调度 | 由主 Agent 拆解和分配工作，根据任务依赖决定串行或并行执行，明确各 Agent 的目标与修改范围，并收集执行结果。 |
| FR-014 | 成果整合 | 支持整合多个 Agent 的工作成果，识别和处理相互冲突的修改。整体任务是否完成，应以整合后的整体结果为准。 |

### 2.4 任务预算、控制与历史

| 编号 | 名称 | 需求 |
| --- | --- | --- |
| FR-015 | 实现次数限制 | 每个编码子任务固定最多三轮实现，包含首次实现及最多两次修复。暂停、恢复或更换执行 Agent 不得重置同一子任务的累计次数；达到上限后应停止并说明未完成原因。 |
| FR-016 | 任务控制与恢复 | 支持澄清后继续、暂停、继续和取消任务；用户能够从已保存的稳定进度显式恢复，保留此前工作、执行记录和剩余实现次数。取消后不再开展新的修改，并说明已有成果及相关服务状态。 |
| FR-017 | 历史记录 | 用户能够查看历史任务及子任务的需求、计划、执行角色、状态、实现次数、Skill 使用情况、命令结果、修改内容、验证结果和提交记录。 |

### 2.5 Skill 创建与检索

| 编号 | 名称 | 需求 |
| --- | --- | --- |
| FR-018 | 手写 Skill | 支持用户以手写文件方式创建和维护 Skill。系统能够识别新增、修改和删除，校验 Skill 是否可用，并向用户说明无效内容或引用缺失的原因。 |
| FR-019 | 个人统一 Skill 库 | 使用个人统一 Skill 库管理所有 Skill，供不同项目复用；能够查看 Skill 及引用资料的来源，并判断其对当前任务的适用性。 |
| FR-020 | RAG 检索 Skill | 根据任务需求检索 Skill 及其引用资料，返回相关候选和来源信息，帮助 Agent 找到适用的工作方法。 |
| FR-021 | 自动选择与用户指定 | 支持 Agent 自动选择适用 Skill，也支持用户明确指定。展示实际使用的 Skill、来源及使用原因；没有适用内容时不得强行匹配，指定内容不存在或不适用时应明确说明。 |
| FR-022 | 内容更新生效 | Skill 及引用资料新增、修改或删除后，后续检索和使用应反映变化。更新失败应向用户反馈，不能将过期内容表示为最新内容。 |

### 2.6 验证与成果交付

| 编号 | 名称 | 需求 |
| --- | --- | --- |
| FR-023 | 测试与运行验证 | 根据任务编写或更新相关测试，并执行所需检查与运行验证，确认修改满足需求且没有破坏应保留的行为。 |
| FR-024 | 真实结果判定 | 任务完成状态必须依据实际执行结果判定。检查未通过、必要验证未执行或整体结果不满足需求时，不得仅凭 Agent 的描述报告成功。 |
| FR-025 | 变更提交 | 每个完成的改动应在全部要求的测试和验证通过后形成对应版本提交，提供修改差异和提交记录；提交失败应如实说明，无需修改时不制造无意义的提交。 |
| FR-026 | 保护已有工作 | 保留用户已有未提交修改和无关文件，任务提交只包含本任务变更。遇到修改冲突时应明确处理，不得静默覆盖用户或其他 Agent 的工作。 |
| FR-027 | 最终结果说明 | 区分成功、失败、待澄清、暂停、取消和无需修改等结果。报告已完成工作、实际验证情况和交付成果；未完成时说明停止原因、已有成果及剩余事项。 |

## 3. 运行与质量要求

| 编号 | 名称 | 需求 |
| --- | --- | --- |
| NFR-001 | 本机个人使用 | 优先满足 Windows 本机个人使用，用户通过浏览器操作；任务记录、成果和个人 Skill 库保存在本机。 |
| NFR-002 | 异常反馈 | 模型不可用、文件操作失败、命令执行失败等异常应向用户提供清晰反馈，不得将异常表示为任务完成。 |
| NFR-003 | 任务连续性 | 任务持续执行、切换 Agent 或恢复后，应保留用户目标、关键约束、已完成工作、待办事项和累计实现次数。 |
| NFR-004 | 执行受控 | 对任务耗时、模型调用量、命令执行时间、输出量和并发执行设置上限。达到上限时停止相关工作，保留已有成果并向用户说明原因；每个编码子任务最多三轮实现的规则保持固定。 |
| NFR-005 | 授权与信息保护 | 文件操作和命令执行应遵守用户授权，Skill 和子 Agent 不得自行扩大操作范围；凭据等敏感信息不得出现在任务上下文、展示内容、报告或提交中。 |
| NFR-006 | 状态与记录一致 | 页面状态、执行记录和最终结果应保持一致，能够区分计划、执行中、已完成和失败，便于用户追踪实际工作。 |

## 4. 当前需求范围之外的能力

- CLI 产品入口、IDE 插件、公网服务和多用户协作平台。
- 用户自定义 Agent，以及执行过程中自动创建新的 Agent 角色。
- 自动生成 Skill、从任务经验自动提炼 Skill，以及各项目独立的 Skill 库。
- 将项目文档或源码作为独立 RAG 检索对象；Skill 明确引用的资料仍属于 Skill 检索范围。
- 异常崩溃或断电后的自动恢复，以及多个用户任务的排队系统。
- 外部部署发布、远程系统运维，以及一次性生成任意规模完整产品。
