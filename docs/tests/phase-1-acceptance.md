# 个人 Coding Agent 第一阶段验收说明

日期：2026-10-31。

依据：[第一阶段设计](../product/coding-agent-mvp-design.md)。本文记录需求、场景与预期结果；Agent 行为验收与测试工具自检需要分别报告，工具自检通过不代表产品验收通过。

## 1. 验收范围

验证 Agent 能够根据自然语言需求检索和理解 Python 项目、先形成固定验收测试、再修改函数，并依据真实执行结果判断成功。实现与修复合计最多三次。暂不验收向量检索、多语言解析和 LSP。

确定性验收使用可控模型响应，实际文件读写、Git 操作、进程执行和结果判定均应由真实 Agent 完成。真实 DeepSeek API 的可用性与模型能力评估单独记录，不作为离线验收测试的前置条件。

## 2. 验收需求

| 编号 | 需求 | 可观察结果 |
| --- | --- | --- |
| R01 | 按需求修改目标函数 | 独立需求判定测试通过，调用方与同名无关函数行为保持正确 |
| R02 | 检索并理解必要上下文 | 任务证据包含目标函数、现有调用方和相关测试的检索或读取结果 |
| R03 | 验收先于实现 | 实现变更前存在固定验收版本与原始实现的执行记录 |
| R04 | 最多三次实现与修复 | 实际实现请求数和任务报告一致，不出现第四次请求 |
| R05 | 依据实际执行结果判断 | 验收与原有测试实际执行；失败、跳过、零测试或报告异常不能被判为成功 |
| R06 | 修改与执行受控 | 无效参数、过期版本、非唯一原文、越界路径和命令超时得到明确处理 |
| R07 | 固定验收不被削弱 | 修复阶段不能修改固定断言、删除或跳过用例换取通过 |
| R08 | 状态可追踪 | 记录需求、验收版本、修改尝试、命令、测试结果、停止原因与产物 |
| R09 | 已有工作得到保留 | 保留用户未提交改动，只在全部检查通过后交付对应 commit |
| R10 | 凭据不泄漏 | 模型请求内容、日志、报告和 Git commit 均不包含测试注入的凭据 |

## 3. 示例项目与测试数据

项目与需求数据见 [fixtures 说明](../../tests/fixtures/README.md)。每个场景均复制示例项目到独立临时目录，初始化 Git 基线，避免污染当前仓库和其他场景。

明确需求为：数字统计模块的 `average` 对空列表返回 `None`，非空列表保持平均值行为，不修改输入，并保留现有调用方和无关函数行为。

| 输入或调用 | 预期 |
| --- | --- |
| `average([])` | `None` |
| `average([0])` | `0.0` |
| `average([7])` | `7.0` |
| `average([2, 4])` | `3.0` |
| `average([-2, 2])` | `0.0` |
| 调用 `average` 后检查 `[4, 2]` | 原列表仍为 `[4, 2]` |
| `summarize([2, 4])` | `"average=3.00"` |
| 无关的单词长度函数 `average(["a", "abc"])` | `2.0` |

样例原有六项测试应全部通过；独立需求判定测试应只暴露空列表需求未满足。最终代码的行为由测试侧持有的独立判定再次核对，避免只相信 Agent 生成的测试或报告。

## 4. 场景与预期结果

| 场景 | 对应需求 | 条件或操作 | 预期结果 |
| --- | --- | --- | --- |
| A01 | R01–R05、R08–R09 | 第一次实现正确 | 次数为 1；真实验收与原有测试通过；最终函数满足独立判定；生成可追踪 commit |
| A02 | R01、R04–R05 | 首次将空列表错误处理为 0，第二次修复正确 | 首次失败证据进入后续模型上下文；次数为 2；最终测试通过 |
| A03 | R01、R04–R05 | 前两次实现错误，第三次正确 | 次数为 3；第三次完成后仍执行验证，再报告成功 |
| A04 | R04–R05、R08 | 三次实现均错误 | 无第四次实现请求；状态失败；保留三个尝试及失败证据 |
| A05 | R01、R03–R05 | 原始项目已满足明确需求 | 执行验收与原有测试后报告无需修改；实现次数为 0；工作区无新增代码变更 |
| A06 | R01、R03 | 需求未明确异常输入的语义 | 提出与行为相关的澄清问题；不修改实现；不猜测期望值 |
| A07a | R06 | 修改工具缺少参数或参数类型错误 | 返回明确错误，目标文件字节不变 |
| A07b | R06 | 文件读取后被外部修改，提交旧哈希 | 拒绝旧版本变更，外部改动得到保留 |
| A07c | R06 | 原文不存在或出现多次 | 拒绝替换，不进行模糊匹配或批量替换 |
| A08a | R06 | 读取或修改使用父目录路径、绝对越界路径 | 拒绝越界操作，外部文件不变 |
| A08b | R06 | 工作区内目录联接或符号链接指向外部 | 按解析后的真实位置拒绝操作；平台无法创建链接时明确报告限制 |
| A09a | R06、R08 | 测试命令持续运行并启动子进程 | 超时结束，清理进程及子进程；记录超时，不报告成功 |
| A09b | R06、R08 | 命令持续输出大量内容 | 按配置限制输出和执行，保留截断或停止标识 |
| A10a | R03、R07 | 修复时放宽固定验收断言 | 拒绝变更，验收文件与固定版本一致 |
| A10b | R03、R07 | 修复时删除验收测试或增加跳过标记 | 拒绝变更，不以删除或跳过后结果判定成功 |
| A11a | R01、R05 | 验收通过，但原有回归测试失败 | 状态未通过，剩余预算内继续修复，不能交付成功 commit |
| A11b | R05 | 命令退出码为 0，但没有执行预期测试 | 状态未通过，记录缺少预期测试的原因 |
| A11c | R05 | 验收跳过，或结构化报告不存在或损坏 | 状态未通过，保留证据，不接受模型的完成声明 |
| A11d | R05 | 项目原有测试在基线就失败 | 明确记录既有失败；未解决前不能宣称所有测试通过 |
| A12 | R04、R08 | 已完成两次失败尝试的任务中断并继续 | 使用相同任务标识，最多只剩一次实现尝试 |
| A13 | R05–R06、R08 | 参数合法，但文件或命令操作实际失败 | 输出真实失败与原因；参数合法不等于执行成功 |
| A14a | R08–R10 | 注入测试用凭据并完成任务 | 报告、日志、事件和 commit 可追踪，且不包含凭据原文 |
| A14b | R08–R09 | 用户已有未提交文件或代码改动 | 原有改动保留，不被覆盖或混入 Agent 的交付 commit |

## 5. 验收入口与运行方式

用户已确认通过 CLI 的 JSON 输入和报告验收，允许本次行为测试处于预期 RED 状态。具体输入、退出码、报告与模型替身协议见 [CLI 验收契约](cli-contract.md)。

行为测试位于 [test_mvp.py](../../tests/acceptance/test_mvp.py)，方法名中的 `A01`–`A14` 与本文场景编号对应。同一编号的边界条件拆为多个可独立运行的方法。文件读写、Git、进程执行和任务持久化均由真实 Agent 完成，测试只替换外部模型。

```powershell
python -B -m unittest discover -s tests/acceptance -t . -p 'test_*.py' -v
```

测试工具自检独立运行：

```powershell
python -B -m unittest tests.test_product_docs tests.test_acceptance_fixtures tests.test_acceptance_harness -v
```

自检核实原始回归通过、原始实现不满足新需求、正确实现通过，以及典型错误实现会被判定失败；同时验证模型替身、JUnit 输出和测试基础设施。自检通过不等于产品行为验收通过。

当前仓库尚未实现 Agent CLI，因此行为测试应明确失败于入口未生成报告；不使用跳过、`expectedFailure` 或模拟整个 Agent 获得通过。后续实现必须使同一套测试实际转绿。

本次实际执行结果见 [验证记录](phase-1-validation.md)。

A12 使用进程退出后的受控检查点恢复验证累计预算与持久化。强制结束进程后的恢复、真实 DeepSeek 连通性与质量、流式输出及 API 传输故障重试暂不在本次执行范围。

## 6. 通过标准

- 所有必需场景实际执行并通过，不能用未实现时的跳过或预期失败标记代替产品通过。
- 固定验收与原有测试全部通过，报告与独立执行证据相符。
- Agent 不修改测试侧持有的独立需求判定数据。
- 离线运行不读取当前仓库真实 `.env`，只使用测试凭据及可控模型。
- 对无法执行的场景明确列出原因；存在未执行的必需场景时，本阶段不算验收通过。
- RED 状态意味着实现尚未满足契约，需要后续实现工作；不得描述为全部验收通过。
